这个环境没有做什么（诚实专栏）

下列是刻意或受验收口径限制而未做的部分。每条给「现状 → 替代方案 → 代价/边界」与文件路径——藏起来才是不诚实。

1 · 记分板：非集中式比对

现状tb/uvm/env/ppa_scoreboard.sv 只做读写计数，CSR 镜像集中比对是 TODO。
替代真正比对分散在自检序列 chk_eq 与 core-agent driver 的内建参考模型 predict()（从 spec 逐条推导；原双份 ppa_ref_model.sv 死代码已按 BUG-016 处置删除）。
代价检查逻辑分散、非集中式记分板，跨组件追溯成本高。

2 · 无 RAL / uvm_reg

现状tb/ 下无 uvm_reg/RAL。
替代tb/uvm/env/ppa_reg_defs.sv 地址常量 package 单点定义。
代价无自动 mirror/predictor，寄存器建模靠手写。

3 · 无 virtual sequence / p_sequencer

现状tb/ 下 p_sequencer 引用 0 处。
替代ppa_base_test 模板方法 main_seq() 组织激励。
代价多 agent 并发编排能力弱。

4 · 无 factory override

现状set_type/inst_override 0 处。
替代场景差异靠独立 test 类。
代价test 类数量线性增长（当前 27 个场景测试类）。

5 · 功能覆盖率只有 1 个 covergroup —— SCORE 是代码域水位，不代表功能空间

现状功能覆盖仅 apb_cg（3 coverpoint + 1 cross）。
替代验收口径是 spec §0 适配 7 的代码+断言六类，功能覆盖率不在判据内。
代价97.46% 是代码域水位，不代表功能空间覆盖（最易被追问的一条）。

6 · 约束随机轻量，非工业级 CRV

现状无独立 constraint 块，靠 $urandom + 多 seed。
替代随机空间靠 seed 数量（回归 32 条 / 27 唯一测试，3 个测试追加多 seed）而非约束建模。
代价随机深度受 seed 数量限制，不是工业级约束随机验证。

以下三条是 0.5.3 起的诚实性排查暴露的，正面写出来——它们证明审查机制在收官后仍在起作用：

7 · 断言曾经不拦回归（BUG-014，两段式）

过去4 个里程碑期间，全仓 49 条断言对回归的拦截力实际为 0：动作块一律 else $error(...)，而回归判 PASS 只看 UVM_ERROR/FATAL，$error 不经 UVM report server、VCS 也不改退出码——同一份 log 中断言真实失败却 UVM_ERROR:0、退出码 0、判 PASS，还能登成 ✅。
现在已修（-assert verbose 原生计数 + 引擎行双层，fail-closed，单点在 scripts/svacheck.py）。断言失败现在会让回归变红（有负向实验背书）。
但必须同时写历史清白是事后复算出来的（定位证据 commit → git archive 重建源码树 → 按 TEST+SEED 重跑，带阳性/保真度对照），不是当时流程保障的。

8 · 注释腐烂与守卫盲区（BUG-013）

现状仓库曾有多处源码注释停在 0.1.x 期（「M3 尚未交付」等），一路带到收官；ppa_scoreboard.sv 两条 TODO 是过期承诺。
根因docs.py --check 只守 doc/、不覆盖源码注释——守卫体系也有盲区，而盲区靠外部人工质疑才暴露（起点正是用户翻代码问「这仓库真做完了吗」）。
现在已补 report.py --check 第 7 项守卫；当前扫描 74 个源文件 / 1023 行注释，过期承诺 0 处。守卫精度优先、召回窄，「通过」只等于「无这几种字面形态」，不等于「无过期承诺」。

9 · lint 曾漏登 10 处（BUG-012）

现状make lint 实测处数一度超过登记表覆盖，是 rev 顺手实跑才发现。
现在已补齐：现 81 处告警 / 12 条豁免全部经 rev 复核（复核 12 条，处数为登记时刻计数）。
边界make lint 至今 exit 1；本轮只修 3 处、其余登记豁免。不写「lint 干净/清零/全部修复」。
